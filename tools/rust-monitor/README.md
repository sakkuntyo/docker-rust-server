# Rust Monitor 0.2.10（Windows / SSH）

SSH と docker exec で Rust サーバーのマップ、接続中・過去に接続したメンバー、本人のインベントリ・ベルト・装備を表示する Windows アプリです。収集プラグインの追加は不要です。

マップ下部にチャットを重ねて表示し、サーバーとして全体へ発言できます。

所持品は Rust の標準アイコンを使ったスロット表示です。空きマス・数量・耐久ゲージを表示し、マウスを重ねると名前や装填数、アタッチメントを確認できます。右側の所持品エリアは、ウィンドウの幅に応じて広く表示します。

## 使い方

1. ZIP を展開し、app フォルダーの RustMonitor.exe を起動します。
2. SSH 接続先を user@docker-host の形で入力し、「一覧取得」を押します。
3. コンテナを選択して「SSH で接続」を押します。
4. 左のメンバーを選ぶと、その人の所持品が表示されます。
5. マップ上の印をクリックしてもメンバーを選択できます。名前と X / Z 座標をマップ上に、X / Y / Z と記録時刻を右側に表示します。
6. メンバー一覧と右側の詳細に「Steam ID」を明記し、その直下に conntrack で確認した「本IP」を表示します。
7. 「接続履歴」には以前接続したサーバーと前回同期時刻を表示します。マウスを重ねると行が強調され、クリックするとそのサーバーへ再接続して30秒ごとの更新を開始します。

ボタンやマップの印にマウスを重ねると、説明や詳細を暗い背景の吹き出しで表示します。長い説明は折り返して表示します。

マップはホイールまたは「＋」「−」で拡大・縮小し、ドラッグで移動できます。「全体」で元の表示に戻り、「選択した人へ」でその人を中心に拡大します。最大16倍まで拡大できます。同じサーバー・ワイプの更新では拡大率と表示位置を維持します。

「名前・座標」でラベルを切り替えられます。密集した場所では一部のラベルを省略するため、印にマウスを重ねるか拡大して確認してください。検索と「オンラインのみ」はマップにも反映されます。緑の印はオンライン、灰色はオフライン・接続未確認、橙色は選択中の人です。

既存の「Docker サーバー一覧」からサーバー行をダブルクリックしても開けます。0.1.x の一覧で保存した SSH 接続先は引き継ぎます。接続先が一度保存されると、次回起動時に前回のデータを表示します。

「接続履歴」はこのアプリの接続先一覧です。サーバーを切り替えると検索と「オンラインのみ」を解除します。同じサーバーを選び直すと再取得します。接続に失敗した場合は理由を表示し、取得済みデータは残します。

Windows 側での RCON ポート・パスワード・TLS の入力は不要です。Windows OpenSSH の鍵認証と登録済みホスト鍵を使用します。SSH 先には python3 と sudo -n docker が必要です。コンテナ内の既存の rcon、jq、curl を利用します。

必要な実行環境は Windows 10/11 と .NET 10 Desktop Runtime です。app フォルダー一式を使用してください。EXE 単体では動作しません。

## 表示する情報と時点

| 情報 | 取得方法・時点 |
|---|---|
| 接続中の人 | コンテナ内の標準 RCON playerlist。取得時点の状態 |
| 本IP | 使用中の中継サーバーの conntrack と接続中のプレイヤーのIP・ポートを照合。確認時刻を記録 |
| 過去に接続した人 | server/all-playerlist.json、今季のセーブに残っている本人、PC の保存履歴 |
| マップ | 今季の server/map-urls.csv に記録された画像をコンテナ内で取得 |
| プレイヤーの座標 | 最新 .sav の本人の位置。オフラインも身体が残っていれば表示。座標のセーブ時刻を明示 |
| インベントリ・ベルト・装備 | 最新の .sav に保存されている本人の所持品。セーブ日時を表示 |
| 数量・耐久値・装填数・入れ子 | セーブに記録されている値。未登録のアイテムは ID を表示 |

座標と所持品は **最終セーブ時点** の記録です。オンラインの印でも座標はセーブ時点で、リアルタイムの追跡ではありません。セーブ後の移動やアイテムの変更は、次のサーバー保存後に反映されます。表示のためにサーバーへ強制セーブは行いません。

オフラインの人も、セーブに本人の身体が残っていれば取得できます。死亡・身体消失などでセーブに記録がない人は、過去の取得結果があれば時刻付きで表示し、未取得と空の所持品を区別します。箱・TC・死体の所持品は収集対象外です。

30秒ごとに同期します。「更新停止」で止められます。アプリを閉じている間の情報は、サーバーに既存の保存処理が記録した範囲を次回起動時に読みます。接続・切断の正確なイベント履歴は SSH 版にはありません。

## 所持品のスロット表示

- アイテム一覧のスクロールバーは非表示です。マウスホイールで上下にスクロールできます。
- プレイヤー名の横の「情報を隠す」でSteam ID・本IP・座標・保存日時などを折りたたみ、アイテム一覧の縦の表示領域を広げます。「情報を表示」で戻せます。表示状態はメンバー変更・更新・次回起動後も引き継ぎます。所持品が未取得の場合の案内は、折りたたみ中も表示します。
- インベントリ24枠、ベルト6枠、装備8枠を表示します。取得したスロット位置を保持し、空きマスを詰めません。追加スロットが記録されている場合は表示を拡張します。
- 右下の数字は数量、下端のゲージは耐久値です。アイコンにマウスを重ねると、名前・スロット・耐久値・装填数・アタッチメントなどの内容物を表示します。
- 画像は [Rust公式Wiki](https://wiki.facepunch.com/rust/item/cloth) が使っている Facepunch の配信元 `https://files.facepunch.com/rust/item/{shortname}_512.png` から、必要な分を取得してPCへキャッシュします。ZIPに画像は同梱しません。Rustの画像はFacepunchに帰属します。
- カスタムスキンの見た目は反映せず、標準アイコンを使います。スキンIDは詳細に表示します。画像が未提供・取得失敗の場合も、アイテム名と数量で表示します。
- 初回の画像取得にはインターネット接続が必要です。キャッシュ済み画像はオフラインでも表示します。所持品の取得方法や保存時点は従来どおりです。

## 本IPの確認

Tailscale の exit node で DNAT/SNAT している構成に対応します。コンテナが実際に使用している中継サーバーを自動取得し、Windows からそのホストにも SSH 接続して `sudo -n conntrack -L` で読み取ります。SSH のユーザー名は Docker ホストで使用中のユーザー名、接続先は中継サーバーの HostName です。Windows の SSH config にホスト別の鍵を指定できます。

中継サーバーに python3・conntrack と読み取り可能な sudo 設定、Windows 側にそのホストの SSH 鍵設定・登録済みホスト鍵が必要です。取得できない場合も他の情報は表示し、本IP欄に理由を表示します。

サーバーのIP・ゲームポートと、プレイヤーの通信でサーバーに見えているIP・ポートの両方を照合します。NATによる送信元ポートの書き換えにも対応します。照合後に Steam ID・IP・ポート・接続経過時間を再確認し、接続が変わった場合や複数の候補がある場合は推測しません。

「本IP」は中継サーバーへ到達した通信の元の送信元IPです。VPN・プロキシをさらにさかのぼった利用者の回線IPを保証するものではありません。

確認済みのIPはサーバー・Steam ID別にPCへ保存します。切断後、照合に失敗したとき、保存済みデータだけを開いたときは「最終確認」と元の確認時刻を表示します。アプリが一度も確認していない過去のメンバーは「未確認」です。現在の通信記録がないオフラインの人について、過去の本IPをさかのぼって復元することはできません。

## サーバーチャット

- マップ下部に重ねて表示します。「▼ サーバーチャット」で折りたたみ、「非表示」またはマップ上部の「チャット」で表示を切り替えます。表示設定は次回起動時にも引き継ぎます。
- 接続中は5秒ごとに `chat.tail 200` で最新200件までを取得します。各発言に日時・チャンネル・名前を表示します。「全体・サーバーのみ」を外すと、取得できたチームなどの発言も表示します。
- 折りたたみ中も取得を続けます。非表示中・更新停止中は取得を止め、再表示時に取得します。過去の発言をスクロールして読んでいる間は、自動で末尾へ移動しません。
- 送信先を確認し、1行256文字までの文章を入力して「送信」または **Ctrl＋Enter** で発言します。日本語変換のEnterだけでは送信しません。
- 発言は `global.say` により **SERVER名義でサーバー全体へ送信** します。これはプレイヤーのチームチャットへの返信ではありません。送信中は接続先の変更を止めます。
- 応答が途切れたときは「送信結果を確認できません」と表示し、入力を残します。既に送信されている場合があるため、自動再送はしません。再送前に履歴を確認してください。
- 最新の取得結果を接続先別にPCへ保存します。全期間のチャット保存ではなく、再起動やサーバー側の履歴上限で失われた発言は復元できません。アプリを閉じている間の発言もサーバーに残る範囲で表示します。

取得は既存のSSH接続を使います。チャットを読み取る操作と、送信ボタンでの発言を分離し、接続・更新だけでは発言しません。

## 欠損・ワイプ・保存中の扱い

- playerlist の空配列は正常な0人です。RCON が失敗した場合は接続状態を「未確認」にします。
- 履歴ファイルが未作成の場合は、取得できた現在のメンバーとセーブの情報を表示します。
- 履歴の addunixtimestamp は初回観測の記録です。最終接続時刻としては扱いません。
- セーブに未知の形式や破損がある場合、所持品を空として上書きせず警告を表示します。
- 所持品はサーバー・ワイプ・Steam ID 別に保存します。別ワイプの所持品は混ぜません。
- ファイルを読み取る前後でサイズ・inode・更新時刻を確認し、保存中に変化した場合は次の同期で再試行します。
- 対応するセーブ形式は288です。Rustの更新で形式が変わった際は読み取り処理の更新が必要です。
- このリポジトリの起動設定に合わせ、server/serverdata1 内の最新 .sav を読みます。対象セーブの作成日時が現在シーズン内であることも確認します。
- マップが未作成・取得失敗でも、メンバーと所持品の取得結果は表示します。
- 座標のない人はマップに印を出さず、右側に理由を表示します。身体消失・保存後の参加・乗り物のボーンに対する相対座標などは位置を確定できない場合があります。通常の親オブジェクトの位置・回転・拡縮はセーブから合成します。
- 座標が画像の範囲外の場合、誤った端の位置に印を出しません。X / Y / Z は右側で確認できます。別ワイプや記録時刻のない旧データはマップに重ねません。
- マップの座標変換は Rust が生成する標準画像の周囲500ピクセルの海の余白に対応します。

## Docker サーバー一覧

| 列 | 取得元 |
|---|---|
| サーバー | 実行中の rust-* コンテナと ENV_SERVERNAME |
| RCON ポート | ENV_RCON_PORT |
| 現在人数 | コンテナ内 RCON playerlist |
| 今季接続人数 | all-playerlist.json の重複を除いた Steam ID 数 |
| 今季最大同時接続数と日時 | docker logs --timestamps の定期記録 |
| 収容可能最大人数 | ENV_MAXPLAYERS |
| シーズン | wipeunixtime と設定周期 |

monthly=35日、bi-weekly=14日、weekly=7日、daily=1日として開始予定を算出します。実際のワイプまでの遅延区間は人数ログから除きます。保存ログがシーズン途中からしかない場合は、その旨を表示します。ピークは定期観測値で、全瞬間の最大ではありません。PC で確認済みのピークはシーズン別に保持します。

## 保存先

既定は %LOCALAPPDATA%\RustMonitor です。

- monitor.sqlite3：メンバー・所持品・接続先・集計結果・最新のチャット取得結果・表示設定
- maps/：ワイプ別のマップ画像
- icons/：Facepunchから取得した標準アイテム画像のキャッシュ
- monitor.sqlite3-wal、monitor.sqlite3-shm：起動中の SQLite 補助ファイル

バックアップはアプリを終了してからフォルダー全体をコピーしてください。保存先を分ける場合は --data-dir D:\RustMonitorData を付けて起動します。

RCON パスワードはコンテナ内でのみ使い、PC に取得・保存しません。スクリプトは SSH の標準入力で実行します。サーバーに常駐プロセスや収集プラグインを追加しません。セーブ本体は Docker ホスト内で解析し、必要なプレイヤー情報だけを PC に返します。管理用ライブラリの解析や DLL はアプリの実行に不要です。

## 開発・検証

.NET 10 SDK と Python 3 を使用します。

~~~powershell
.\build.ps1
.\check.ps1
py -3 -m unittest discover -s .\tests -p 'test_*.py'
~~~

SQLite の永続化、サーバー・ワイプ分離、欠損と0人の区別、セーブ内の数値・ネスト、破損・非対応バージョン、SSH 入力検証、WPF の保存済み表示を検証します。画面の検証画像は artifacts 以下へ出力します。

実際の公式画像の取得も確認する場合は、以下を実行します。ネイティブセーブと同じ数字のアイテム識別子を使い、キャッシュがない状態から画像の取得・画面への反映まで検証します。サーバーへの接続は不要です。

~~~powershell
dotnet run --project .\tests\RustMonitor.Checks.csproj -c Release -- .\artifacts\live-icons --live-icons
~~~

0.1.x の直接 WebRCON 接続用コード・プラグインのソースは開発資料として残っていますが、0.2.x の画面と配布物は SSH 方式です。

アイテム名の対応表は [uMod の公開 Rust Definitions](https://umod.org/documentation/games/rust/definitions) に基づきます。対応表にない新しいアイテムは ID で識別できます。
